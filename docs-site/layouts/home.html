GET STARTED

Run it. Tunnel it. Open it.

Run the daemon where your agents live, connect your devices, and open the client.

On your agent host

LINUX / macOS

Keep your tmux sessions running. With uv and tmux installed, start the daemon:

GEMINI_API_KEY=your-key uvx --from git+https://github.com/querystory/tmux-rc.git tmux-rc

Get a Gemini API key from aistudio.google.com; it powers summaries and answers. No key? Run heuristics-only. Configure Live Mode for chat and voice.

Full setup guide →Run as a persistent service →

Give your devices a private route

TAILSCALE

Install and sign in to Tailscale on the host and your devices. Before exposing the daemon, review your tailnet ACLs: every permitted member can read pane data and control terminals. Then run on the host:

tailscale serve --bg http://127.0.0.1:18030

Open the HTTPS address printed by Tailscale. Keep the daemon on loopback, on a machine only you use: loopback does not keep out other accounts on the same host. It has no built-in login; Serve access follows your tailnet ACLs, so restrict access to trusted operators, especially on shared tailnets.

TALK, THEN KEEP GOING

A conversation with your fleet.

Use text chat or an active voice session from desktop or phone. Ask what your agents are doing, relay an instruction, and hear a follow-up when the work you directed changes.

  • “Which agents need me?” — get a fleet update.
  • “Show me e2e triage.” — get an Open button.
  • “Tell it to rerun with tracing.” — send an instruction.
  • “Press Escape in that pane.” — send a control key.
  • “Resume the checkout session.” — find and resume earlier work when session history is installed.

Chat offers pane-changing actions for approval. Voice follows your spoken instructions and reports back; routine fleet updates stay quiet.

AFTER A REBOOT

Your whole fleet, back in one tap.

A reboot takes every tmux session with it. tmux-rc records the layout once a minute and which conversation each agent holds, then offers the lost workspace back: every session, window and split where it was, each agent resumed into its own conversation on the account it ran on.

  • Recently active agents start ticked; long-idle agents and plain shells are yours to add.
  • An agent already running elsewhere is greyed out, with the reason.
  • Nothing comes back until you tap Restore, and Start fresh drops the offer.

ARTIFACTS FOR ANY AGENT

Review agents’ work where it happens.

Your agents publish planning docs, drafts, mocks and reports as pages on their own machine, beside the repo and the pane that made them. There’s nothing to upload and no hosted, vendor-locked service: any model, any harness, any script that writes a file can publish one.

  • A gallery that knows the fleet: each page links back to the pane that made it.
  • A link before the page: it reads In progress, then notifies you when it lands.
  • HTML, or a Markdown viewer with tables, mermaid diagrams and callouts.
  • Reply to the maker from the page, with a screenshot attached.

MAKE ROOM BEFORE YOU RUN OUT

Keep an eye on your limits.

Running a fleet can use a subscription window fast. Claude and Codex meters show how much you’ve used, when each window resets, and where your current pace is heading.

  • Track separate accounts and their available plan windows.
  • See usage trends and projections.
  • Amber and red warnings flag a tight window; “full in” estimates time to exhaustion.

Projections estimate your current pace; they don’t guarantee how much work remains.

How usage tracking works →

KEEP YOUR FLEET MOVING

See activity over time.

The dashboard shows how many panes and background agents are working, idle, compacting, waiting, or asking for you. Set a running-agent goal and compare it with the moving average.

  • Explore a day, three days, a week, or a month of history.
  • Compare activity by tmux session or agent tool.
  • Filter the population and zoom into a stretch of work.
  • Open the full Graph to see every pane and its sub-agents, grouped by session, repo, worktree or tool.

Activity counts show agent states, not token throughput or CPU utilization.
